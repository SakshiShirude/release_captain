Slide 2 • Problem

Release decisions are usually fragmented and slow.

  • Evidence lives across commits, pull requests, changed files, CI runs, and tags.
  • Version bumps are often guessed instead of justified from actual change impact.
  • Release notes get rushed and end up as low-quality commit dumps.
  • Teams either automate too aggressively or slow everything down with manual checks.

The hackathon opportunity

Build an agent that behaves like a release engineer: gather evidence, reason over change impact, write the release story clearly, and stop at a strict human gate before doing anything dangerous.

The value is not “AI generates text.” The value is AI turning repository state into a controlled decision workflow.
Why this matters: releases are where code quality, safety, and business impact meet. 2 / 5
Slide 3 • Workflow

The agent follows a strict release workflow from analysis to approval.

1
Create session

Input a repository URL, branch, optional previous tag, and allowlisted test command.

2
Collect evidence

Read commits, merged PRs, changed files, tags, and recent GitHub Actions runs.

3
Analyze impact

Categorize features, fixes, docs, refactors, chores, and detect major change signals.

4
Recommend version

Generate the next semantic version and polished release notes from evidence.

5
Wait for approval

Stop at ready_for_approval with an auditable plan and clear release context.

6
Execute with control

Only after exact approval: create the tag or release through governed execution steps.

This is a stateful backend workflow, not a one-shot prompt response. 3 / 5
Slide 4 • What is real today

The backend already does real release reasoning and safe control flow.

Real GitHub analysis

Parses the repo, selects a baseline, compares changes, and gathers CI evidence through the GitHub API.

Semver recommendation

Maps commit evidence into major, minor, or patch with deterministic logic and breaking-change detection.

Executive-style release notes

Outputs structured release notes that summarize value, fixes, docs, and change impact more clearly than raw commits.

Approval integrity

Approval succeeds only if repository, recommended version, and proposed actions exactly match the plan.

Clear execution outcomes

Post-approval actions return explicit, auditable outcomes so teams always understand what happened next.

Multi-mode test handling

Supports demo mode, analysis mode, and a local runner path for practical repository evaluation workflows.

Strongest differentiator: auditable automation with human control. 4 / 5
